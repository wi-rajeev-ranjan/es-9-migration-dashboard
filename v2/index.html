Carried forward from V1 discussions

Agreements so far — edit or challenge in the sections below.

  • One service for now: wi-matching-engine-ms with internal wi_matching_engine/ module; optional PyPI split later.
  • Integrated plan: P0–P2 = adapter infra migration; P3–P4 = engine v0 (embed) + v1 (match_jobs experiment); post-P4 = ingest cutover only.
  • Query path: apps call matching engine API — engine reads matching ES, does not HTTP-call profile-ms on hot path.
  • Consistency: Postgres = truth; matching ES = eventual projection; lag + DLQ + backfill are operational requirements.
  • Triton: inference-ms embedding API used inside L5 enrich pipeline — not called by app microservices.
